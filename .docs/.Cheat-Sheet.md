## Line-by-Line: The `watchPosition()` Call

From `src/app/services/geo.ts`, lines 22–33:

```typescript
async startWatching() {
  this.watchId = await Geolocation.watchPosition(
    { enableHighAccuracy: true },
    (position, err) => {
      if (position) {
        this.liveCoords.set({
          lat: position.coords.latitude,
          lng: position.coords.longitude
        });
      }
    }
  );
}
```

| Part | What it does |
|---|---|
| `await Geolocation.watchPosition(...)` | Registers a continuous GPS listener with the device's native hardware. Returns a **string** (the watch id), not a Position. |
| `{ enableHighAccuracy: true }` | Options object — tells the device to use precise GPS hardware instead of rough network-based location. |
| `(position, err) => { ... }` | Callback function — called by the native layer every time the device detects a position change. Receives either a valid `position` object or an `err`. |
| `position.coords.latitude` / `.longitude` | The actual coordinate numbers extracted from the `Position` object's nested `coords` property. |
| `this.liveCoords.set({ ... })` | Pushes the new coordinates into the Angular signal, which automatically triggers any `effect()` or template binding watching it. |
| `this.watchId = ...` | Stores the returned string id so `stopWatching()` can pass it to `clearWatch()` later. |

## Q&A — Likely Questions

**Q: What's the difference between `getCurrentPosition()` and `watchPosition()`?**
> `getCurrentPosition()` is a one-shot — it returns a single Position through a Promise, gives you lat/long at that instant, and it's done. `watchPosition()` is continuous — it registers a callback that fires every time the position changes, and it keeps firing until you call `clearWatch()`.

**Q: What does `watchPosition()` return, and why do you store it?**
> It returns a string — the watch id. We store it in `this.watchId` because it's the only way to tell `clearWatch()` which watcher to stop. Without it, we'd have no way to release the GPS listener.

**Q: What does `clearWatch()` actually do?**
> It tells the native layer to remove the GPS listener that was registered by `watchPosition()`. After that, the callback simply stops being called — the hardware is released and the app stops receiving position updates.

**Q: What happens if you press Stop without ever pressing Start?**
> Nothing breaks. `stopWatching()` checks `if (this.watchId)` first — if it's `undefined` (no active watcher), it skips the `clearWatch()` call entirely.

**Q: Why did you disable the Start button while watching?**
> To prevent creating duplicate watchers. If the user pressed Start twice, we'd have two active GPS listeners but only one `watchId` stored — the first watcher would become orphaned and impossible to stop.

**Q: Where does the accuracy option come from, and what does `enableHighAccuracy` do?**
> It's part of the Capacitor Geolocation plugin's options. Setting it to `true` tells the device to use its GPS hardware for precise coordinates instead of falling back to less accurate Wi-Fi or cell tower triangulation.

**Q: Why is the service class named `Geo` instead of `Geolocation`?**
> Naming it `Geolocation` would collide with the Capacitor plugin import `import { Geolocation } from '@capacitor/geolocation'` — the compiler wouldn't know which one you mean. The guide specifically warns about this.

**Q: How do the live coordinates reach the template?**
> The service's signal `liveCoords` gets updated by the `watchPosition` callback. In the page's constructor, an `effect()` watches that signal — every time it changes, the effect runs and writes the new values to `this.latitude` and `this.longitude`, which the footer reads via `{{ latitude }}` and `{{ longitude }}`.

**Q: What's the difference between `startLatitude` and `latitude`?**
> `startLatitude` / `startLongitude` are set once in `ngAfterViewInit` from `getLatLng()` and never change. `latitude` / `longitude` start with the same initial value but get overwritten by the `effect()` every time a new live position arrives.
