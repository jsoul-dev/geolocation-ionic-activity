## Segment 4 — Member 4: Conceptual Explanation & Wrap-up (~45–60 seconds)

**Spoken cues:**

- "`getCurrentPosition()` and `watchPosition()` are both from the Capacitor Geolocation plugin, but they work differently."
- "`getCurrentPosition()` is a one-shot call — it returns a single `Position` through a Promise, gives you lat/long at that instant, and it's done."
- "`watchPosition()` is continuous — it registers a callback with the device's native GPS hardware, and that callback fires every time the position changes. It doesn't return a Position — it returns a **watch id string**, which is basically a handle you keep so you can stop it later."
- "`clearWatch()` takes that id and tells the native layer to remove the GPS listener. After that, the callback simply stops being called — the hardware is released."
- "In our code, we store the watch id in `this.watchId` inside the service. When the user presses Stop, we pass it to `clearWatch()` and set it back to `undefined` so we know there's no active watcher."
- "That's the key idea from Unit 2's learning objective 7 — track live movement with `watchPosition()`, release hardware resources with `clearWatch()`."
- "Thanks for watching."
